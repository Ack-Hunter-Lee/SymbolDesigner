# 传送带（Belt）图元实现计划

## 1. 概要

新增一种图元类型 **`Belt`（传送带 / 皮带）**：由"两条自由端点 + 若干被绕行的圆（滚轮）"定义，实时求解出**一条**由直线段（圆与圆之间的公切线）+ 圆弧（绕圆包络弧）组成的单条路径，输出为一段 `M / L / A / Z` 的 PathData，渲染为**单线描边 Path**（无填充），并由 XAML 导出管道导出为可直接做流动动画的 `<Path Data="..." Stretch="None">`。

用户需求（原话）：

- "圆和圆之间相切的线是传送带，最终其实是一个path，我到时候需要设置动画，用于表示这个传送带在运行"
- "皮带不应该规定形状，最好是能实现两个拖动点，在拖动的时候，自动与圆的形成相切轨迹，就是物理世界中真的把一条带子在各个轮子之间穿行一样，到最终把带子的两端闭合，就形成一个带子了"

已确认的设计决策（用户已回答）：

| 决策点 | 选定 |
| --- | --- |
| 参与绕行的圆 | **全画布圆，只绕挡路的**（自动判定，不要求用户逐个指定） |
| 绕行侧（左/右绕） | **拖动时由用户决定并记住**（拖动过程中按当前几何择侧，结果持久化） |
| 闭合后是否可继续编辑 | **仍可继续编辑** |
| 皮带线型 | **单线**（纯描边，无填充/无带宽语义） |

## 3. 方案设计

### 3.1 数据模型

`Belt` 采用**"拓扑 + 端点"**模型：几何**不落盘**，每次由拓扑 + 端点 + 滚轮实时求解。

`PrimitiveItem`（[PrimitiveItem.cs](file:///f:/Codes/CSharp/SymbolDesigner/Models/PrimitiveItem.cs)）新增：

```csharp
/// <summary>皮带绕行拓扑（有序）：每一项 = 一个被绕行的圆滚轮 + 绕行方向。
/// 顺序 = 从自由端点 A 到 B 依次穿行的圆；Wrap = +1 顺时针绕 / -1 逆时针绕（WPF sweep 语义）。
/// 持久化字段；几何由 VM 的 BeltSolver 实时求解，不落盘。</summary>
public List<BeltAnchor> BeltAnchors { get; } = new();

/// <summary>两个自由端点（画布坐标）。IsClosed=true 时表示"两端已闭合"，两点应重合。</summary>
[ObservableProperty] private double _beltStartX;
[ObservableProperty] private double _beltStartY;
[ObservableProperty] private double _beltEndX;
[ObservableProperty] private double _beltEndY;

/// <summary>BeltSolver 解出的路径（局部坐标 mini-language：M/L/A/Z），由 VM 求解后写入。
/// 不落盘（每次由拓扑+端点+滚轮重算）。渲染/导出/选中装饰都读它。</summary>
[ObservableProperty] private string _beltPathData = string.Empty;

public System.Windows.Media.Geometry? BeltGeometry { get; }   // Geometry.Parse(BeltPathData) 缓存
```

`BeltAnchor` 值对象（新文件或放 `Models/BeltAnchor.cs`）：

```csharp
public sealed record BeltAnchor(Guid CircleId, int Wrap);
```

`IsClosed` 复用已有 `[ObservableProperty] private bool _isClosed`（[PrimitiveItem.cs](file:///f:/Codes/CSharp/SymbolDesigner/Models/PrimitiveItem.cs#L340)）。

**为什么几何不落盘**：滚轮随时可被编辑；只存拓扑 + 端点 → 打开工程、拖动任一滚轮都能重算出正确的皮带。同时避免"存了旧 PathData、滚轮动了却对不上"的经典不一致。

**`X/Y/Width/Height` 语义**：不再是"用户摆放位置"，而是**求解结果的包围盒**（与 BooleanPath 的语义一致）。因此：

- **Belt 整体拖动 = 同时平移两个自由端点**（滚轮不动）。这样"拖动整体"是可预期的（皮带整体平移，绕行形状由滚轮决定不变）。
  实现在 `DraggablePrimitive.OnDragDelta` 加分支：`item.BeltStartX += e.HorizontalChange; item.BeltStartY += e.VerticalChange; item.BeltEndX += ...; item.BeltEndY += ...;` 再调 `vm.SolveBelt(item)`。
- **不允许对 Belt 做 `GeometryMath.RecalcBoundingBox`**（它只认 `M/L`，会因 `A` 指令出错）。

#### 3.2.1 两圆外公切线

皮带绕在滚轮**外侧**，故只取**外公切线**（外切线）：

```
D = |C2 - C1|；若 D < |r1 - r2| + eps → 退化（一圆内含另一圆），返回 null
θ = atan2(C2.Y - C1.Y, C2.X - C1.X)
α = asin((r1 - r2) / D)
φ = θ ± α                                  // 两条外切线的方向角
n = (-sin φ, cos φ)                        // 单位法线
P1 = C1 + r1 * n ,  P2 = C2 + r2 * n       // 两条切线的接触点对
校验：|P2 - P1| ≈ sqrt(D² - (r1 - r2)²)
```

返回两个候选 `(P1, P2)`（`φ = θ+α` 与 `φ = θ-α`）。

#### 3.2.2 点到圆的切点（自由端点接触第一个/最后一个滚轮）

```
L = |P - C|；若 L <= r + eps → P 在圆内/圆上，无切线
切点距圆心 r，且切点 ⊥ (P-切点)：两解可解析求出
取与目标 Wrap 方向一致的解
```

#### 3.2.3 绕行弧

从入射接触点 `Pin` 绕到出射接触点 `Pout`，按 `Wrap` 方向沿圆走：

```
a0 = atan2(Pin - C) ; a1 = atan2(Pout - C)
Δ = Wrap == +1 ? Nor(a1 - a0) : Nor(a0 - a1)     // Nor 归一到 (0, 2π]
若 Δ < 2° → 该锚点实际未被绕行 → 标记为"待剔除"
否则输出： A r,r 0 {largeArc},{sweep} Pout
          largeArc = Δ > π  ? 1 : 0
          sweep    = Wrap == +1 ? 1 : 0
```

#### 3.2.4 组装

- **开放（`!isClosed`）**：
  - `anchors.Count == 0` → `M A L B`。
  - 否则：`M A` → `L 切点(A→C₀)` → 对每个 anchor：绕行弧 → `L 外切线接触点(Cᵢ→Cᵢ₊₁)` → 最后 `L 切点(Cₙ₋₁→B)` → `L B`。
- **闭合（`isClosed`）**：
  - `anchors.Count < 1` → `Degenerate = true`（一个圆的皮带无意义）。
  - 环序 `C₀→C₁→…→Cₙ₋₁→C₀`：每相邻对用**外切线**连接，每个圆用**绕行弧**；最后 `Z`。

最后：把画布坐标路径整体平移到包围盒左上角为原点 → 得到局部坐标 `PathData`，同时输出 `Origin / Width / Height`。

任一步骤退化（外切线 null / 切点 null / 弧 < 2°）→ 该锚点按"降级"处理：跳过该圆的弧，仅直连（保证不崩、不跳变）；整条无解则返回 `Degenerate = true` 且回退为 `M A L B`。

#### 3.2.5 自动绕行（`AutoEngage`）——"只绕挡路的"

```
第 1 步：按 current 拓扑解出当前路径，拆成线段表（弧段也按弦/端点近似参与判定，见下）
第 2 步：循环（最多 32 轮）
   在"未收录的圆"中找【穿入当前路径最深】的圆 C：
     - 对每条直线段：线段是否穿过 C 的内部；穿入深度 = max(0, R - 圆心到线段距离)（且垂足在线段内）
     - 自由端点 A/B 落在某圆内部时：把该圆视为挡路（深度 = R - |端点-圆心|）
     - 取深度最大者
   若无 → 跳出
   确定插入位置 k = 该圆"穿入的那条线段"在拓扑中的序号（拓扑序列 = [A] + anchors + [B]，线段 j 连 节点 j-1 → 节点 j）
   确定 Wrap（见 3.2.6）
   anchors.Insert(k, (C.Id, Wrap))
第 3 步：剔除"弧 < 2°"的锚点（不再阻挡的滚轮自动脱开）
第 4 步：返回新拓扑
```

**顺序自然正确**：每轮插入的是"当前路径上冲突最严重的圆"，插入位置由它破坏的线段决定 → 从 A 到 B 的穿行次序自动成立（这就是"橡皮筋"迭代法的收敛性质）。

#### 3.2.6 Wrap（绕行侧）的选择 —— "拖动时由用户决定并记住"

- 若该圆**已在当前拓扑中**（含拖动期间的历史缓存）→ **复用已记住的 Wrap**，不再反复重算（避免抖动）。
- 若是**首次收录**：
  1. 分别算出 `Wrap = +1 / -1` 两个候选的**总路径长度**；
  2. 取较短者（物理紧边绳的自然结果——"真的把一条带子穿行过去"）；
  3. 若两者相差 < 1%（左右对称的歧义情形）→ 取**与上一帧解出的路径最接近**的那一侧（连续性原则）：直觉上"用户往哪边拖，就从哪边绕"；
  4. 结果写入拓扑并**记住**（拖动结束后随工程落盘）。
- 拖动过程中若某已收录圆的当前 Wrap 会导致**绕行弧 > 200°**（说明当前侧几何上不合理）→ 对该圆重新择侧并覆盖。

这样"用户通过拖动决定 + 结果被记住"两个要求同时满足，且不需要额外的 UI 开关。

```csharp
/// <summary>传送带导出：单线描边 Path，Data = 求解出的 M/L/A/Z（含真弧）。
/// Stretch=None → 坐标即局部坐标，下游可直接对 StrokeDashOffset 做流动动画。
/// 无 Fill（单线语义），无 StrokeDashArray（动画由使用方按需施加）。</summary>
private static string BeltElement(PrimitiveItem p, string left, string top, string z, ExportContext ctx)
{
    var geom = p.BeltGeometry;
    if (geom is null) return Comment("Belt 未求解出几何，无法导出");
    string dataStr = System.Security.SecurityElement.Escape(geom.ToString(CultureInfo.InvariantCulture));
    return $"<Path Canvas.Left=\"{left}\" Canvas.Top=\"{top}\" Data=\"{dataStr}\" Panel.ZIndex=\"{z}\""
         + $" Stroke=\"{ctx.StrokeExpression}\" StrokeThickness=\"{ctx.StrokeWidthExpression}\""
         + $" StrokeLineJoin=\"Round\" StrokeStartLineCap=\"Round\" StrokeEndLineCap=\"Round\""
         + $" Stretch=\"None\" />";
}
```

## 5. 假设与决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 滚轮定义 | 复用 `GeometryMath.IsCircleLike` / `TangentSolver.TryGetCircle`（`Ellipse` + `Ring`） | 与既有"相切/重合约束"的圆定义保持一致，避免第二套语义 |
| 皮带线型 | 单线描边、**不可填充**（`IsFillable=false`） | 用户选定"单线" |
| 几何落盘 | **不落盘**，只存拓扑 + 端点 | 滚轮可编辑 → 必须能重算；避免旧几何与新滚轮不一致 |
| `X/Y/W/H` | = 求解结果包围盒，不是用户摆放坐标 | 与 BooleanPath 语义一致 |
| Belt 整体拖动 | 平移两个自由端点 | 绕行形状由滚轮决定，平移端点即可整体位移 |
| 绕行侧 | 首次收录取较短侧（对称歧义时取与上一帧最近侧），收录后记住 | 满足"物理紧边绳"+"拖动时由我决定并记住" |
| 是否支持多皮带 | 支持（每条独立求解，互不干扰） | 成本为零 |
| 是否支持轴吸附 | 不支持 | 端点是"绳头"，几何由求解器决定，吸附无意义 |
| 是否给属性面板加专属分组 | 阶段 1-3 不加 | 通用外观分组（描边/透明度）已够；`IsFillable=false` 自动隐藏填充组 |
| 弧段是否摊平 | 不摊平，输出真弧 `A` 指令 | 用户要"一个 path"；真弧让导出体积小、动画顺滑 |
| CLI 编辑端点 | 阶段 3 不做（仅创建/渲染/查询） | 端点属结构字段，超出白名单语义；需要时再单独评估 |
