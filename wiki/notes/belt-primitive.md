# 图元类型：传送带（Belt）—— 相切穿绕的皮带几何

## 需求

要画出"滚轮 + 绕在轮子上的皮带"这类设备图形（多个圆 + 圆之间的公切线），且最终产物必须是**一条连续的 path**，以便下游对它做 `StrokeDashOffset` 流动动画表示"皮带在跑"。

现有工具做不到，原因有三：

- 画线工具的几何序列化 `GeometryMath.BuildPathData` 只输出 `M / L`，**没有弧输出入口**；
- `L1Primitive` 枚举里没有弧、没有皮带；
- 约束求解 `TangentSolver` 只支持"**一个圆 ↔ 一条直线**"相切，没有"两圆公切线"。

## 交互模型（用户已确认的四条决策）

| 决策点 | 结论 |
| --- | --- |
| 参与绕行的圆 | **全画布圆，只绕挡路的**（自动判定，不要求用户逐个指定） |
| 绕行侧（左绕/右绕） | **拖动时由用户决定并记住**（结果落盘），不做额外 UI 开关 |
| 闭合后 | **仍可继续编辑** |
| 线型 | **单线**（纯描边，无填充 / 无带宽语义） |

即"真的把一条带子在各个轮子之间穿行"：两个自由端点 + 若干被绕行的圆 → 实时解出路径；把两端点拖到一起（< 3px）闭合，就成了传送带环。

## 数据模型：拓扑 + 端点，几何不落盘

`PrimitiveItem` 只持久化两样东西：

- `BeltAnchors`（有序拓扑）—— 每项 = `{ 被绕行圆的 Id, Wrap }`，顺序 = 从自由端点 A 到 B 依次穿行；
- `BeltStartX/Y`、`BeltEndX/Y`（两个自由端点，画布坐标）+ 复用的 `IsClosed`。

**求解出的 PathData 不落盘**（`BeltPathData` 只是运行时字段，`ToDto` 不写它，`CreateFromDto` 也不读）。理由：

- 滚轮（Ellipse/Ring）随时可被拖动/缩放，存下来的旧几何立刻与新滚轮对不上；
- 打开工程、拖任一滚轮都能**重算**出正确皮带 —— 单一事实来源是"拓扑 + 端点 + 滚轮"，而不是一份会过期的几何快照。

代价是：**任何"恢复 Primitives 集合"的路径都必须补一次重算** —— 工程加载（`FromSymbolProject`）、撤销/重做恢复、滚轮几何变化（`OnItemGeometryChanged` 的早退**之前**）、拖动滚轮都各挂了一个 `SolveBelt*` 调用。漏一处就会出现"皮带形状是旧的"。

`X / Y / Width / Height` 的语义随之改变：不再是"用户摆放位置"，而是**求解结果的包围盒**（与 `BooleanPath` 一致）。因此：

- **整体拖动 = 同时平移两个自由端点**（`DraggablePrimitive.OnDragDelta` 特判），绕行形状由滚轮决定；
- **不能对它调 `GeometryMath.RecalcBoundingBox`**（只认 `M/L`，遇 `A` 会算错）。

## 几何求解（`Geometry/BeltSolver.cs`，纯函数静态类）

不依赖 `PrimitiveItem`，输入是轻量结构（`BeltRoller` / `BeltAnchorSpec`），故 GUI 与 CLI 可共用。

- **两圆公切线**：相邻两轮绕行方向**相同 → 外公切线**（皮带在外侧）；方向**相反 → 内公切线**（交叉带）。
  外公切线：`α = acos((r1-r2)/D)`，`ψ = θ ± α`，法线 `n = (cos ψ, sin ψ)`，切点 `c_i = C_i + r_i·n`。
- **点到圆切点**：自由端点接触第一个/最后一个滚轮。
- **绕行弧**：从入射接触点按 `Wrap` 方向沿圆走到出射接触点；`Δ = Wrap>0 ? Nor(a1-a0) : Nor(a0-a1)`；
  `largeArc = Δ > π`，`sweep = Wrap>0 ? 1 : 0`。**输出真弧 `A` 指令，不摊平**（一个 path、导出小、动画顺滑）。
  弧角 `< 2°`（`MinWrapAngle`）视为"根本没绕"→ 该锚点自动脱开。
- **组装**：开放 = `M A → L 切点 → (弧 → L 公切线)… → L B`；闭合 = 环序 `C0→C1→…→C0` 每对走公切线、每轮走绕行弧，末尾 `Z`。
  任一步退化（切线/切点无解）→ 逐个移除肇事滚轮重试；彻底无解 → 回退直线 + `Degenerate = true`，**保证不崩不跳变**。
- **最后**把画布坐标路径整体平移到包围盒左上角为原点 → 局部坐标 `PathData` + `Origin/Width/Height`。

## 自动绕行 `AutoEngage`：橡皮筋迭代 + Wrap 择侧记忆

**收录（"只绕挡路的"）**：把当前拓扑解成路径，在"未收录的圆"里反复找**穿入当前路径最深**的那个圆，插入到它破坏的那条线段对应的拓扑下标，迭代至收敛（上限 32 轮），并剔除弧 < 2° 的锚点。顺序自然正确 —— 每轮插入的是当前路径上冲突最严重的圆，这就是橡皮筋法收敛性的来源。

**Wrap 择侧**（"拖动时由我决定并记住"）：

1. 该圆已在拓扑中（或本轮拖动已记住）→ **复用已记住的 Wrap**，不反复重算（防抖动）；
2. 首次收录 → 算 `+1 / -1` 两条候选路径的总长，**取较短者**（物理紧边绳的自然结果）；
3. 两者相差 < 1%（左右对称的歧义情形）→ 沿用拖动期记忆 `_beltWrapMemory`（"用户往哪边拖就从哪边绕"）；
4. 已收录圆的绕行弧 > 200°（`MaxWrapAngle`）→ 说明当前侧几何不合理，翻侧并覆盖。

**闭环自举**：闭合且拓扑为空时，A/B 不参与闭合几何、没有橡皮筋初始线段可依据 → `AutoEngage` **以全部滚轮为初始环（按 X/Y 排序）** 再交给迭代收敛/剔除。GUI 的常规路径（先画开放绳、再拖到闭合）已有拓扑，不走这里；此分支覆盖"直接创建/加载 closed 皮带"。

## 导出与动画（`XamlExporter.BeltElement`）

导出为**单线 Path**：`<Path Canvas.Left=… Canvas.Top=… Data="M…L…A…Z" Stretch="None" Stroke=… StrokeThickness=… StrokeLineJoin/StartLineCap/EndLineCap=Round />`，**无 Fill**（单线语义）。

下游做"皮带在跑"动画：给该 Path 加

```xml
<Path StrokeDashArray="4 4">
  <Path.Triggers>
    <EventTrigger RoutedEvent="Loaded">
      <BeginStoryboard>
        <Storyboard RepeatBehavior="Forever">
          <DoubleAnimation Storyboard.TargetProperty="StrokeDashOffset"
                           From="0" To="-8" Duration="0:0:0.5" />
        </Storyboard>
      </BeginStoryboard>
    </EventTrigger>
  </Path.Triggers>
</Path>
```

`Stretch="None"` 是关键：坐标即局部坐标、线宽不被缩放，虚线间隔与偏移才匀速"流动"。

## CLI 侧（`sym`）

`Validate` 加别名 `belt`（`points` 恰为 2 个自由端点）；`DslToProject` 只写端点、**不写 PathData**，随后由 `BeltDtoGeometry.AutoEngageAll` 对该工程整体跑一次 AutoEngage + Solve（写回拓扑与包围盒）；`Renderer` 复用同一个 `BeltDtoGeometry` 求解后离屏绘制。

`BeltDtoGeometry` 存在的理由：几何不落盘 → **渲染/创建都必须现算**，而 GUI 的 `TangentSolver.TryGetCircle` 吃 `PrimitiveItem`，CLI 只有 DTO。故按同一语义在 DTO 上重建（圆类 = `Ellipse`/`Ring`，半径 = `min(w,h)/2`，Ring 再扣 `RingStrokeHalfThickness`），供 `DslToProject`（创建时写拓扑）与 `Renderer`（渲染）共用一份，避免两处漂移；`RingStrokeHalfThickness` 常量也收口在此，Renderer 复用。

## 同一滚轮可被绕多次（蛇形 / S 形回程二次接触）

**需求**：皮带绕过大圆 → 绕小圆一圈 → 回来应能**再次绕大圆**（机械里常见的 S 形绕法）。早期实现只能绕一次。

**早期实现的三道锁**（都在 `ResolveNodes` / `FindBlocker` / `AutoEngage` 的清理步）：
1. `ResolveNodes` 用 `seen` HashSet 按 Id 去重 → 拓扑里同一 Guid 只能出现一次；
2. `FindBlocker` 用 `engaged.Contains(r.Id)` 跳过已收录滚轮 → 回程段穿过它也不收录；
3. 清理步按 Id 一刀切剔除"没绕"的滚轮 → 会同时抹掉同一圆的另一次合法收录。

**改法**（拓扑本就是有序 `(CircleId, Wrap)` 列表，持久化天然支持重复 Guid，无需改格式）：
1. `ResolveNodes` 去掉 `seen`，允许同一 Guid 产生多个 `Node`；
2. `FindBlocker` 去掉 `engaged` 守卫，改为"与**别的**已收录滚轮相交则跳过"（`n.Id != r.Id`）→ 同圆自身可二次收录；
   端点落圆内那条分支仍保留 `engaged` 守卫（否则会造出"相邻重复项"，必然无解）；
3. 清理步改为**按出现顺序+额度**保留：统计每个 Id 的"真绕弧（≥2°）数量"当额度，前 quota 次保留，多出的（回程只是擦过）剔除。

**收敛性**：终止条件不变（"没有圆穿入任何线段"）——正确绕行的圆不再被穿过，故不会无限循环。

**已知保守取舍**：
- `TryFlipOversized`（绕行弧 >200° 且翻侧更短 → 翻 Wrap）对**出现多次**的圆跳过：`Op` 只带 `NodeId` 分不清是第几次出现，翻错会破坏已收敛拓扑。代价是这类圆的 Wrap 不会自动纠正。
- 相邻重复项（`[大圆, 大圆, …]`）在 `CircleTangent` 里 D≈0 无解，由 `Build` 的降级逻辑剔除。

**验证**：手写拓扑 `[大圆, 小圆, 大圆]`（两个自由端停在大圆左侧中部）→ 皮带在大圆**上/下各绕一段弧**、小圆绕约 180°，单条连续 path。`AutoEngage` 走 `current` 作为种子（`new List<>(current)`），故 GUI 拖动端点时是**增量收录**：回程段一旦穿过已收录的大圆即插入第二次出现。

**为什么 CLI 端到端测不出这一条**：CLI 的 `AutoEngageAll` 只对"尚无拓扑"的皮带跑，且种子是 A–B 直线段。若两个自由端点都停在同一侧，A–B 直线不穿过任何圆 → 什么都收不进来（这是"不挡路就不绕"的正确行为，非 bug）。二次收录只可能发生在**已有拓扑**（即 GUI 拖动）的增量路径上。

## 踩坑：点切点只看"切点 − P"，B 侧出口方向取反未处理 → 单圆两段切线不对称

**现象**：单个圆、画一条穿过圆的线段，得到的不是"两段近似对称的切线 + 一小段弧"，而是一段切线贴着圆顶、另一段贴着圆底，中间绕行弧膨胀成 **159°**（大半个圆），看起来像"C"形。

**根因**：`PointTangent` 从外部点算切点时有两个候选，用"行进方向 · Wrap 绕行方向 > 0"筛掉错的那个。但它恒按 `行进方向 = 切点 − P` 判定 ——
这只对 **A 侧入口**成立（皮带从 A 走向切点）；**B 侧出口**皮带是从切点走向 B，行进方向应为 `P − 切点`，与前者**恰好取反**。
取反未处理 → 出口选到了圆的**另一面**切点 → 两切点分居圆两侧 → `MakeArc` 的弧角从最小弧（本例 24.7°）膨胀到 158.9°。
数值核对（A=(110,53)、C=(230,180)、r=100、B=(480,240)）：错误出口 80.6°（圆底）→ 弧 158.9°、总长 657；正确出口 306.4°（圆右上）→ 弧 24.7°、总长 423.5，与"物理最短绳"一致。

**修复**：`PointTangent` 增加 `bool isStartPoint`，`AssembleOpen` 分别传 `true`（入口 A）/ `false`（出口 B），
行进方向按 `isStartPoint ? 切点−P : P−切点` 取值。修正后弧最小、两切点关于"圆心指向 A–B 最近点的半径"近似对称，
即"皮带包住圆的近侧"。

**顺带验证到的取舍**：修好后 `AutoEngage` 会正确**跳过不挡路的圆**（例：端点连线离圆心 150px、圆半径 70px → 直接画直线，不再强行绕行）；
被绕行的圆若绕行弧 < 2° 会被自动脱开。

**仍开放的议题**：`AutoEngage` 是**逐个插入 + 每次取当前最短**的贪心，不是全局最优；多轮子且半径差异大时可能产出
"相邻两轮 Wrap 相反"（内公切线 / 交叉带）的结果 —— 那是当前上下文里的最短绳，但视觉上是"扭一圈的皮带"。
若产品上要求传送带恒为 **非交叉**（Wrap 全同），应改为"优先与邻居 Wrap 一致，仅当几何不可行时才允许反转"，而不是纯比总长。

## 经验

- **"几何不落盘 + 实时重算"要付记账成本**：凡是重建集合的路径（加载 / 撤销重做 / 滚轮变化 / 整体拖动）都得挂重算钩子。省了落盘一致性，换来的是"钩子漏一处就形状过期"。适合"源数据可编辑且求解便宜"的场景（滚轮少、求解 O(滚轮数²) 以内）。
- **橡皮筋迭代法的收敛性来自"每轮收录冲突最深的那个"**：不需要全局排序，天然得到 A→B 的正确穿行次序。
- **对称歧义要有"记忆"兜底**：两条候选路径长度几乎相等时，"取较短者"不稳定（浮点抖动会让侧别跳变），必须叠加"沿用上一帧"的连续性规则，交互才不抖。
- **真弧比摊平折线更适合做动画**：`A` 指令体积小、曲率精确，`Stretch="None"` + `StrokeDashArray` + 循环 `StrokeDashOffset` 即得匀速流动。
- **同一几何在两个消费方（GUI/CLI）都要用时，先抽公共求解入口**：否则 DTO 版与模型版各写一份"圆类判定 + 半径修正"，早晚漂移。
